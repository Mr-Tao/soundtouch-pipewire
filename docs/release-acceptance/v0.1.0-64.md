The installed daemon, controller, and debug packages are all `0.1.0-64` from
the hashes above. The preflight passed with the companion stopped, the service
started once with no restart, and four distinct Device/Route/Node sets remained
published through four finite digital-silence sessions. On the representative
receiver, native PipeWire volume, native mute/unmute, PulseAudio-compatible
volume while muted, and an external receiver-side update all converged to fresh
physical readback. The receiver safely ignored the muted decrease; both desktop
views rolled back to the unchanged physical value rather than retrying it.

A user-started media stream appeared on the fourth receiver during acceptance,
so its physical volume remained at zero and testing paused. After that stream
ended, the same silent Route checks passed there. All four receivers were then
restored to their initial generic source and exact volume/mute state. The
service is enabled; only proof from a newly started user manager remains
incomplete because the current manager predates this installation.
